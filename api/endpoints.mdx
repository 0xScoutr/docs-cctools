All 48 endpoints live under `https://api.cctools.network`, return the
standard `{ data, pagination, meta }` envelope, and require the `X-API-Key`
header. The one exception is `/api/v1/public/status`, which needs no key and
answers with its payload directly.

List endpoints accept `?limit=` and `?offset=`. The common shape is a
default of 50 and a maximum of 200, but several lists cap lower (50 or 100)
and a few ignore `limit` entirely. Read the `limit` echoed back in
`pagination` rather than assuming. A value outside the accepted range is
clamped to the nearest valid one silently; it never returns an error.

`pagination.total` is the real total on most lists. On `/news` and
`/markets/tokens` it is only the size of the page you got back, so paginate
until you receive fewer items than your `limit` instead of comparing against
`total`.

<Note>
Replace `cck_...` with one of your keys from
[/profile/api](https://cctools.network/profile/api). An interactive explorer
with a live Send button is at [cctools.network/api-docs](https://cctools.network/api-docs).
</Note>

<Warning>
**Cold cache.** Most endpoints served from a cron-warmed cache answer `503`
with code `warming_up` rather than returning an empty body. Treat that as a
retry, not as an empty result. Three behave differently and are worth knowing
before you build on them: `/governance` and `/network/stats` answer `200`
with null or zero fields, and `/featured-apps/{slug}` answers `404`, which is
indistinguishable from a slug that does not exist.
</Warning>

<Warning>
**There is a per-IP ceiling on top of your key's limit.** Every request to
`/api/`, on every tier including Validator, counts against 600 requests per
minute per IP address. Sustained breaches escalate to a temporary IP block, so
back off when you see a `429` instead of retrying immediately. If you need a
higher ceiling for a backfill, ask before you run it.
</Warning>

<Note>
The Use column says whether the endpoint's data may be used in a commercial product (Data plans) or is for personal use, and the Source column where the data comes from. The plans and their limits are in [Plans and limits](/api/plans).
</Note>

## Ecosystem

Projects, categories, rankings, trending.

| Endpoint | Description | Use | Source |
|---|---|---|---|
| `GET /api/v1/public/ecosystem/categories` | List categories with counts | Data plans | CCTools ecosystem directory |
| `GET /api/v1/public/ecosystem/projects` | List projects | Data plans | CCTools ecosystem directory |
| `GET /api/v1/public/ecosystem/projects/{slug}` | Get project by slug | Data plans | CCTools ecosystem directory |
| `GET /api/v1/public/ecosystem/projects/{slug}/analytics` | Engagement analytics for a project | Personal use | CCTools engagement analytics |
| `GET /api/v1/public/ecosystem/projects/{slug}/campaigns` | Project campaigns | Data plans | CCTools ecosystem directory |
| `GET /api/v1/public/ecosystem/projects/{slug}/token` | Project token stats | Personal use | DexScreener, cached by CCTools |
| `GET /api/v1/public/ecosystem/rankings` | Projects ranked by metric | Personal use | CCTools ecosystem directory, ranked by upvotes, views and clicks |
| `GET /api/v1/public/ecosystem/trending` | Top 20 trending projects this epoch | Data plans | CCTools ecosystem directory, scored from upvotes, views and clicks |

```bash
curl -H "X-API-Key: cck_..." \
  "https://api.cctools.network/api/v1/public/ecosystem/categories"
```
