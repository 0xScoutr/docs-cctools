The CCTools Public API gives you programmatic, read-only access to the same
Canton Network data that powers cctools.network: the ecosystem directory,
earn campaigns, leaderboards, public user profiles, governance, news, and
live network statistics.

## Base URL

```
https://api.cctools.network
```

The keyed endpoints live under the `/api/v1/public/` prefix and return JSON.
One more route, paid per call over x402 instead of a key, lives under
`/api/v1/x402/`: see [Pay per call with x402](/api/x402).

## Authentication

Every `/api/v1/public/` endpoint except `/api/v1/public/status` requires an API
key, sent in the **`X-API-Key`** header. There is no `Authorization: Bearer` scheme, and a
Bearer header is rejected.

```bash
curl -H "X-API-Key: cck_your_key_here" \
  "https://api.cctools.network/api/v1/public/network/stats"
```

A key comes with a plan on your account: see Plans at a glance below.
Generate and manage keys at [cctools.network/profile/api](https://cctools.network/profile/api).
See [Authentication](/api/authentication) for the full flow.

## Response envelope

Successful responses share one shape:

```json
{
  "data": { "...": "..." },
  "pagination": { "limit": 50, "offset": 0, "total": 491 },
  "meta": { "tier": "pro", "rate_limit_remaining": 60, "daily_limit_remaining": 999 }
}
```

- `data`: the payload (object or array, depending on the endpoint).
- `pagination`: present on list endpoints; `null` otherwise.
- `meta.tier`: the plan of your key: `evaluation`, `pro`, `data`, `data_team`, `validator`, or `paid` for Enterprise.
- `meta.rate_limit_remaining`: your per-minute ceiling.
- `meta.daily_limit_remaining`: the calls you have left today under your plan's daily cap; `null` when your plan has none.

Errors are `{ "error": "message", "code": "..." }` with an HTTP status of
`400`, `401`, `404`, `429`, or `503`. A `503` with code `warming_up` means a
cron-warmed dataset has a cold cache: retry in a minute rather than treating it
as an empty result.

## Plans at a glance

A key has the plan of the account that made it. The per-minute limit counts requests for each key and endpoint; the
daily limit counts calls for the whole account over a UTC day.

| Plan | Use | Per minute | Per day | How |
|---|---|---|---|---|
| **Evaluation** | Testing only | 60 a minute | 1,000 a day | A key our team issues on request |
| **Pro** | Personal use | 60 a minute | 1,000 a day | Included with [CCTools Pro](https://cctools.network/pro). Instant, self-service at /profile/api |
| **Data Starter** | Commercial use, with attribution | 120 a minute | 20,000 a day | Bought in Canton Coin at /profile/api, monthly or annual |
| **Data Team** | Commercial use, with attribution | 600 a minute | No daily cap | Bought in Canton Coin at /profile/api, monthly or annual |
| **Validator** | As approved by the Development Fund Committee | No per-key limit | No daily cap | Submit your party ID; reviewed by a person, usually within one business day. Free for 12 months |
| **Enterprise** | Commercial use inside your product, under an agreed order | No per-key limit | No daily cap | Contact us |

Every plan, Validator included, also sits under a ceiling of 600 requests per
minute per IP address across the whole API.

Prices, the number of keys each plan allows and the full table are in
[Plans and limits](/api/plans), generated from the API spec. The same figures are at
[cctools.network/api-docs](https://cctools.network/api-docs), and the terms that
apply to every plan are at [cctools.network/terms/api](https://cctools.network/terms/api).

## Free with no key

These need no key and no account, and all of them are served from `https://api.cctools.network`:

- The open daily network record, under `/api/open/network-record/v1/`, published under CC BY 4.0.
- The feeds aggregators read, under `/api/markets/`.
- The status endpoint, `/api/v1/public/status`.
- The OpenAPI file, `/api/v1/openapi.json`.
- The MCP server, `/api/mcp`.

Everything else under `/api/v1/public/` needs a key.
